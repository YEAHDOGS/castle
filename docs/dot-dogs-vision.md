# Dot Dogs — the long-term play

Brandon's vision (2026-09-09): if you can't beat them, join them — then replace them.
A dogs-only internet: a `.dogs` namespace with its own rules, reachable only
through a Castle.

## The rules of Dot Dogs (examples)
- No cookie banners — because there are no cookies. Tracking is a protocol violation.
- No logins to use an app. Open, use, done.
- No ads that follow you. No dark patterns. Builders sign a conduct oath or they don't ship.

## How it's actually possible (honest version)
- A public ICANN `.dogs` TLD costs six figures in application fees — not the path.
- The real path: **an alternate namespace resolved by Castle hardware.**
  Every Castle runs a local resolver that answers `.dogs` names; outside Castle,
  they don't exist. Same trick as Tor's `.onion`, minus the tor.
- Castle is already a router replacement — so the rules get **enforced at the
  gateway**: strip cookies, block trackers, kill fingerprinting at the network
  layer. The "no cookies" law isn't a policy doc, it's packet filtering.
- Mesh later: Castles peer with each other (Yggdrasil-style), so Dot Dogs
  services stay up with no central server and no cloud bill.

## Stance
Long-term. Parked until Castle blocks are real hardware in real homes.
No code until then — this doc is the seed.
